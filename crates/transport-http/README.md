# spiritstream-transport-http

Axum 0.7 + utoipa HTTP transport adapter for `spiritstream-core`.
Versioned REST under `/api/v1/*` plus a WebSocket event channel at
`/api/v1/events`.

## What this crate is

A thin shell around the business logic that lives in `crates/core`.
Every handler in `src/v1.rs` is `Result<Json<T>, ApiError>`: extract
inputs, delegate to a `crates/core` service, map `CoreError` to an
HTTP status once in `src/error.rs`. No business logic in this crate.

## Middleware stack

Layered from outermost to innermost (request flow direction):

1. **`request_id_middleware`** — UUID v7 from
   `X-Request-Id` header or freshly generated; echoed in the response.
2. **CORS** — origin allow-list shared with the CSRF layer.
3. **Cookie manager** — populates the cookie jar for downstream.
4. **`csrf_middleware`** — `Sec-Fetch-Site` primary check
   + Origin allow-list fallback; WS upgrades guarded.
5. **`rate_limit_middleware`** — per-endpoint keyed
   limiters (login 5/min/IP, chat 20/min/identity, streams
   10/min/identity, oauth 5/min/identity, default 300/min/identity).
6. **`DefaultBodyLimit::max(2 MB)`**.
7. **`auth_middleware`** — session cookie membership check (active-session
   set) OR Bearer-token validation.

## Cloud-mode startup guard

When `SPIRITSTREAM_DEPLOY_MODE=cloud` the server refuses to start
unless **both** preconditions are satisfied:

* `SPIRITSTREAM_API_TOKEN` is set and ≥ 32 chars.
* `SPIRITSTREAM_BEHIND_TLS_PROXY=1` is declared (operator confirms a
  TLS-terminating reverse proxy is in front).

`enforce_cloud_mode_preconditions` is a pure function; tests pass the
TLS-declared flag directly so they're parallel-safe.

## Per-service health

`GET /api/v1/health` returns `{ status, services: { profiles,
settings, themes, audit_log } }` where each service status is one of
`ok` / `degraded` / `disconnected` / `tampered`. The aggregate
`status` field is preserved for backwards compat (Tauri sidecar
polling, Docker `HEALTHCHECK`).

## OpenAPI

`GET /api/v1/openapi.json` returns the OpenAPI 3.0.3 document
generated by utoipa annotations on every handler. Consumed by
`packages/api-client` (TypeScript) and by future SDK generators.

## Tests

```bash
cargo test -p spiritstream-transport-http
```

* **27 unit tests** in `phase_6_tests` mod — `SessionCookieMode`
  detection, CSRF Origin matcher, cloud-mode preconditions,
  `mask_sensitive` proptest, hashed bearer ct_eq.
* **45 integration tests** in `tests/http_surface.rs` — real server
  bootstrapped on a free port against a temp data dir, full
  `/api/v1/*` surface verification, legacy-path 404 enforcement,
  CSRF middleware E2E, login brute-force lockout E2E, audit-log
  HMAC chain status, X-Request-Id round-trip, typed health report.
